# 手機體驗審查與改進計劃

2026-09-25。以 UX 設計師的角度檢查整站，重點是手機。

**方法。** 讀了公開頁、會員區和共用元件的原始碼，並在本機 `pnpm dev`（剛重建的 corpus）上用 Playwright 以
375px（iPhone 13/14/15）和 320px（iPhone SE／小安卓）兩種寬度、`isMobile + hasTouch` 實測，逐頁量了：橫向溢出、
內容寬度、可點元素小於 44×44 的數量、每個字級的字元數、表單字級、`<h1>` 行高。

**一個限制。** 容器連不到 `images.wildrunner.org`，所以截圖裡的圖片是空框。版面尺寸不受影響：
`<img width>` 不管圖片載入與否都決定排版寬度。下文凡是跟圖片載入有關的說法都標了「待 staging 確認」。

## 一、結論先講

**字體要調大嗎？要。不過不是整體放大，而是把「太小的那一層」拉上來。**

- 內文 15px 本身不算災難（中文手機閱讀的舒適區在 16–18px），但**文章正文**應該調到 17px。
- 真正的問題在 10–12px 這一層：日期、標籤、報名狀態、篩選 chip、相片說明。賽事頁 **41%** 的字元小於
  14px，相冊頁 **95%**，野馬頁 **70%**。而「報名」連結這種頁面上最重要的操作也只有 11px。
- 表單字級只有 14px（登入頁也是），iPhone Safari 在聚焦時會**自動放大整頁**，這是每個會員每次登入都會遇到的。

**比字體更急的，是四個在手機上直接壞掉的版面 bug**（第三節 P0）：文章列表橫向溢出 1654px、標題換行後疊字、
全站左右留白加倍、文章封面圖只有半寬。

**觸控目標普遍太小。** 賽事頁 106 個可點元素中有 97 個小於 44×44；頁首的登入按鈕只有 16×16，選單按鈕 24×40。

## 三、發現（依優先級）

### P0 — 手機上直接壞掉的東西

**1. 文章列表整頁可以橫向拖動（375px 溢出 1654px）。**
`posts/page.tsx:45-57`：卡片圖片外框是 `flex … overflow-hidden`，`<Image>` 帶著原圖的 `width`（約 2000）且沒有
`w-full`。卡片是 grid item，預設 `min-width: auto`，所以 grid 軌道被撐到圖片原寬。截圖裡標題「2024深圳100越野賽參賽紀實」
被切掉一半。修法：圖片加 `h-full w-full object-cover`，或卡片加 `min-w-0`。

**2. 頁面標題換行就疊字。**
`page-header.tsx:12`：`text-4xl … leading-3`，也就是 36px 的字配 **12px 行高**。一行時看不出來，兩行時第二行直接
壓在第一行上。實測 `/races/utmb-chianti/2027`：「Chianti Ultra Trail」和「2027」疊在一起。用到 PageHeader 的頁面有
文章、賽事、單場賽事、野馬、關於；長賽事名在手機上一定會換行。修法：`leading-tight`（1.25）。

**3. 全站左右留白加倍，相冊三倍。**
`app.tsx:36` 的 `<main className="container">` 已經有 16px padding，每一頁自己又包一層 `container`，
相冊再多一層（`gallery/layout.tsx:23` + `gallery-page-client.tsx:90`）。結果：一般頁 32px、相冊 48px。
375px 的螢幕丟掉 64–96px，大約是正文每行少 4–6 個字。頁首用的是 `px-2` + container，跟內容也對不齊（24px 對 32px）。
修法：只留一層。建議拿掉 `app.tsx` 那層的 `container`，保留各頁自己的（各頁有不同的 `max-w-*`）。

**4. 文章封面圖在手機上只有半寬。**
`posts/[...slug]/page.tsx:290`：`w-1/2 max-w-[720px]` 在所有寬度都生效，手機上約 155px 寬；
`sizes="(max-width: 768px) 90vw"` 卻按 90vw 下載，等於下載了兩倍像素只顯示一半。修法：`w-full md:w-1/2`。

**5. 表單字級 < 16px，iPhone 聚焦時整頁放大。**
`ui/input.tsx:27`、`:45` 是 `text-sm`（14px）；登入頁自己手寫的兩個 input（`members/login/page.tsx:97`、`:108`）也是；
編輯器的區塊類型選單、媒體篩選的 `<select>`（`media/filters.tsx:134`）、朗讀的語音選單是 `text-xs`（12px）。
會員每次登入都會被放大，放大後還要自己捏回來。修法：輸入控制項統一 `text-base md:text-sm`。

### P1 — 讀不清、點不準

**6. 10–12px 的資訊層。** 最嚴重的幾處：

| 位置 | 目前 | 內容 |
|---|---|---|
| `RegistrationStatus.tsx:58,68,75` | 11px | 報名狀態、抽籤類型、**「報名」連結** |
| `RaceSeriesTag.tsx:36`、`RaceQualifierTag.tsx:41` | 11px | 系列、資格賽標籤 |
| `RaceEntryRow.tsx:150,158` | 10px | 進行中 / 已結束 |
| `RaceCalendar.tsx:57,95` | 11px | 月曆星期、日期 |
| `TranscodeBadge.tsx:50` | 10px | 影片轉檔狀態（含失敗） |
| `UploadPanel.tsx:510-536` | 11px | 上傳檔名、完成、**錯誤訊息**（還被 `truncate` 截斷，全文只在 `title`，手機看不到） |
| 各 chip（`filters.tsx:49`、`RaceScheduleFilters.tsx:50`、`RiderFilters.tsx:47`、`RiderViewTabs.tsx:44`） | 12px | 篩選、分頁 |
| 大量錯誤訊息（PostEditor、Avatar、Cover、Password、AI 面板…） | 12px | 錯誤 |

另外，已結束的賽事整列 `opacity-60`（`RaceEntryRow.tsx:121`），11px 的灰字再打六折，對比度明顯不足。

**7. 觸控目標。**
- 頁首登入圖示 16×16，無 padding，手機上也沒有文字（`site-header.tsx:46-53`，`hidden sm:inline`）。
- 選單按鈕 `p-0` 讓寬度只剩圖示的 24px（`site-header.tsx:59`）。
- 手機選單項目 27px 高、間距 24px 點不到（`mobile-nav.tsx:21,28`）。
- 所有 chip：`px-3 py-1` ≈ 25px 高。賽事頁頂部三排 chip 全是。
- 賽事月曆 / 列表切換、「更早 / 更晚」翻頁（`races/page.tsx:168,184`，無 padding，約 16px 高）。
- 分享按鈕 25px；朗讀按鈕 34px；會員區 `Button size="sm"` 36px、編輯器工具列 ≈24px、文章列表刪除「✕」無 padding。
- 反例（做得對的）：`UploadPreview.tsx:205` 的圖片寬度按鈕已經是 `min-h-[2.75rem] min-w-[2.75rem]`，註解也寫了原因。
  這就是全站應該遵守的規範。

**8. 手機選單本身。**（`mobile-nav.tsx`）
- 沒有遮罩：選單下方的頁面照樣露出、照樣可以捲動（截圖可見）。
- `h-[calc(100vh-4rem)]`：iOS 的 `100vh` 包含瀏覽器工具列底下那塊，應該用 `dvh`。
- 沒有 Esc 關閉、沒有 focus 管理、背景不鎖捲動。
- 深色模式開關占了頁首最好的位置，語言切換卻藏在選單最底，且只有 `text-xs py-0.5`。
- `MobileLink` 同時讓 `<Link>` 導航又自己 `router.push` 一次（`mobile-nav.tsx:72-73`），**待確認**是否會多一筆瀏覽紀錄
  （使用者按返回要按兩次）。

**9. 文章閱讀。**（`globals.css:167+` 的 `.article-body`）
- 字級沒設，繼承 body 的 15px；`p` 用 `leading-relaxed`（1.625），比全站的 1.8 還緊，中文偏擠。
- 段距 `mb-3`（12px）不到一行高，段落之間分不開。
- 日期顯示「October 13, 2024」（`lib/utils.ts:11`，寫死 `en-US`），在中文頁面上很突兀。

### P2 — 流程與資訊架構

**10. 賽事頁在手機上太長、起點不對。** 列表頁 16,853px 高（約 21 個螢幕）。清單從本月 1 號開始，
所以使用者一進來先看到的是一串「已結束」。頂部三排 chip 又占掉第一個螢幕的一半。

**11. 賽事月曆在手機上只有點、不能點。** 手機版每場賽事只是一個 6px 方塊（`RaceCalendar.tsx:109-123`），
格子不是連結也不是按鈕；使用者看得到「這天有比賽」，卻沒有任何方法知道是哪場。

**12. 相冊的列高不隨螢幕變。** `MediaGrid.tsx:304` `targetRowHeight={220}`、`PhotoGallery.tsx:32` `350`。
在 224–279px 寬的欄裡，幾乎每張都一列一張，直幅照片非常高。燈箱工具列最多約 10 個按鈕，375px 放不下（待實機確認）。
首頁精選輪播 5 秒自動換，只有 `pauseOnMouseEnter` 能暫停，手機沒有滑鼠；它的「info」按鈕對應的面板被註解掉了，點了沒反應。

**13. 會員區。**
- 編輯器工具列不 sticky；鍵盤彈起後捲動就找不到格式按鈕。儲存／發布也在頁面頂部，寫到一半要捲回去；儲存訊息同理看不到。
- 拖曳區塊的把手只靠 `onMouseEnter` 顯示、用 HTML5 drag（`DraggableBlockPlugin.tsx:51-58`），觸控裝置上看不到也用不了，
  卻仍占著 `pl-6` 的左側空間（`ContentEditor.tsx:120`）。
- 選取文字的浮動工具列沒有限制在畫面內（`SelectionToolbarPlugin.tsx:76-77`），會跟 iOS 原生的選取選單打架。
- 對話框（MediaPicker / MediaDetail）不是全螢幕、背景不鎖捲動、MediaDetail 沒有頂部關閉鈕也不支援 Esc；
  刪除確認狀態下的底部按鈕列不換行，320–375px 會溢出。
- 文章列表每列：標題 `truncate` + 右側一串不縮的 meta，手機上標題會被擠到零寬。
- 會員區主區塊在所有寬度都是 `p-6`（`members/(dashboard)/layout.tsx:22`），320px 只剩 272px。
- 上傳區的主標是「把照片或影片拖進來」——手機不能拖。

**14. 中英夾雜。** 文章列表標題是「Posts」、首頁「Latest Posts」、文章底部「See all Posts」、空狀態「No Posts found」，
全是寫死的英文；頁尾「Created by」也是。中文站上的英文 UI 字串會讓人覺得是半成品。

### P3 — 打磨

- **動態效果**：`prefers-reduced-motion` 只有時間軸頁處理了（`TimelineMotion.tsx:36`）。首頁 marquee 永遠在跑、不能暫停，
  而且 4 份 × 20 張 = 80 個 `PhotoCard`，每個都掛一個 resize listener；每次換頁（包括點篩選 chip，因為 key 含 query string，
  `PageTransitionEffect.tsx:112`）整頁淡入淡出重掛。
- **沒有 `themeColor`、沒有 apple-touch-icon / web manifest**：加到主畫面時沒有圖示，手機瀏覽器網址列也不跟品牌色。
- 首頁「最新文章」卡片圖片固定 `w-[200px] h-[120px] object-contain`，手機上留黑邊。
- 相簿卡片名稱 `truncate`，手機上無法看到全名。
- 頁尾連結 12px。

## 四、字體方案

原則：**正文放大一級、資訊層設下限、標題縮一級。** 手機空間窄，大標題會吃掉第一屏，小字卻讀不到。

| 層級 | 目前 | 建議（手機） | 建議（≥768px） | 備註 |
|---|---|---|---|---|
| 全站 body | 15px / 1.8 | **16px** / 1.75 | 16px / 1.75 | 列表、說明文字 |
| 文章正文 `.article-body` | 15px / 1.625 | **17px / 1.85** | 18px / 1.85 | 段距 `1em`；桌面行寬上限約 36–40 字（`max-w-[40em]`） |
| 頁面 H1（PageHeader） | 36px / **12px** | **30px / 1.25** | 36px → lg 48px | 修 P0-2 的同時縮一級 |
| 文章 H1 | 36px / 1.25 | 30px / 1.3 | 36px | |
| 卡片標題 | 24px | 20px | 24px | 列表卡片 |
| 次要資訊（日期、作者、計數、說明） | 12–14px | **14px** | 14px | |
| 標籤、chip、狀態 | 10–12px | **13px** | 12–13px | 全站**禁用 10px、11px** |
| 表單 input / select / textarea | 12–14px | **16px** | 14px | 防 iOS 自動放大 |
| 錯誤訊息 | 12–14px | **14px** | 14px | 錯誤不能比正文小兩級 |

做法：在 `tailwind.config.ts` 定義語意字級（`text-meta`、`text-tag`、`text-body`、`text-article`），然後把散落的
`text-[10px]` / `text-[11px]` / `text-xs` 換成語意 token。這樣以後改一處就全站生效，也能寫一條規則
（`scripts/assert-*` 或 eslint）禁止再出現 `text-[10px]` / `text-[11px]`。

## 五、觸控規範

- **所有可點元素的點擊區 ≥ 44×44px**（Apple HIG；WCAG 2.5.8 的最低線是 24px，但 44 才是舒適）。
- 視覺可以小，點擊區不能小：chip 視覺 32–36px 高，靠 `min-h-11` 或 `relative` + `before:absolute before:-inset-y-2`
  擴大點擊區。文字連結同理。
- 相鄰目標之間至少 8px，避免誤觸。
- `Button` 元件：手機預設改 `h-11`，`size="sm"` 只在桌面用。
- 延用 `UploadPreview.tsx` 那段已寫下的教訓：**觸控目標上的控制項放在正常流中、一直可見，不靠 hover 顯示。**

## 六、各頁的具體方案

**頁首（全站）。** 手機上只放三樣：Logo、登入／頭像（44×44，登入後顯示頭像縮圖）、選單（44×44）。
深色模式和語言切換移進選單。頁首與內容用同一個左右邊距。

**手機選單。** 全螢幕面板（`inset-0`，高度 `100dvh`），半透明遮罩、鎖背景捲動、Esc／點遮罩關閉；每項 56px 高、17px 字、
左側圖示 20px；當前頁用品牌紫色 + 左側色條標示；底部放「語言」和「深色模式」兩列，各自是完整一列的點擊區。
導覽順序建議：文章、相冊、賽事、野馬、關於，登入後加「會員專區」。（本機 corpus 的選單沒有「賽事」，那來自 CMS 的
site globals，請確認正式站的設定。）

**文章列表。** 修溢出；手機卡片圖 16:9 `object-cover` 滿寬；標題 20px；日期改中文格式；「Posts」換成字典裡的「文章」。

**文章頁。** 封面滿寬；正文 17px / 1.85、段距 1em；分享、朗讀按鈕 44px；作者 handle 14px。
底部「上一篇 / 下一篇」如果有的話做成整塊可點的卡片。

**賽事頁（改動最大，也最常用）。**
1. 預設捲到「今天」，已結束的賽事預設收合成一列「顯示本月已結束的 N 場」。
2. 手機上三排篩選 chip 收成一條：左邊「列表 / 月曆」切換，右邊一個「篩選 (2)」按鈕，點開是 bottom sheet，
   裡面才是系列、報名中、資格賽的選項。第一屏就能看到賽事。
3. 賽事卡片：日期 + 名稱放大為第一層；系列、資格賽標籤 13px；報名狀態 13px；**「報名」做成卡片右下角 44px 高的按鈕**。
   賽事名稱若連到官網，加一個外部連結圖示，手機上看得出是連結。
4. 已結束賽事：不要整列 `opacity-60`，改成只把日期與狀態變灰，文字維持可讀對比。
5. 月曆（手機）：格子變成按鈕，點某一天在月曆下方展開當天的賽事清單（agenda）；有報名中賽事的日子用紫點。
   或更簡單：手機預設只給列表，月曆當成桌面功能。

**相冊。** 修三層留白；`targetRowHeight` 依寬度（手機約 140–160）讓一列能放 2–3 張；
chip 改 44px 點擊區、篩選列可橫向捲動；燈箱在手機上只留 關閉 / 分享 / 播放 三個，其餘收進「⋯」。

**野馬。** 個人頁：手機上頭像放標題上方而非旁邊（目前 88px 頭像 + 36px 名字讓簡介只剩 148–203px 寬）；
時間軸縮小左側縮排和徽章（64px → 48px），讓文字至少有 200px 寬。

**會員區。**
- 登入：input 16px、加上 `autoComplete="email"` / `"current-password"`，讓密碼管理器能自動填入。
- 編輯器：工具列 sticky 在頂部（`sticky top-0`），手機上改為單列可橫向捲動；儲存 / 發布做成底部固定列
  （`fixed bottom-0` + `pb-[env(safe-area-inset-bottom)]`），狀態訊息顯示在這一列裡。
- 觸控裝置上隱藏拖曳把手並回收 `pl-6`；區塊排序改用「上移 / 下移」選單。
- 對話框：手機上全螢幕（`inset-0`，`100dvh`），頂部固定標題列 + 關閉鈕，鎖背景捲動，支援 Esc；底部按鈕列可換行。
- 上傳區：觸控裝置顯示「選擇照片或影片」而不是「拖進來」；錯誤訊息完整顯示（不 truncate），至少 13px。
- 文章列表：手機上一列拆兩行（標題一行、meta 一行），刪除鈕 44px。

## 八、需要你決定的事

1. **正文字級**：建議全站 16px、文章 17px。若會員年齡層偏高，可以直接文章 18px。
2. **手機導覽**：建議先把漢堡選單做好（第 2.5 項）。底部分頁列（文章／相冊／賽事／野馬）是另一個選項，
   適合「賽事頁是高頻工具」的情況；可以等 Cloudflare Web Analytics 看了手機流量與各頁比例再決定。
3. **賽事列表預設隱藏已結束的賽事**：會改變目前的行為和 URL 參數，需要你同意。
4. **賽事月曆在手機上**：做「點日期展開清單」（較費工），還是手機只給列表？
5. **深色模式開關移進選單**：頁首會更乾淨，但切換要多點一下。
